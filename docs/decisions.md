# บันทึกการตัดสินใจ

เรียงจากใหม่ไปเก่า

| วันที่ | การตัดสินใจ | เหตุผล |
| --- | --- | --- |
| 20 พ.ย. 2569 | การแก้ไขและบำรุงรักษา (แก้ข้อผิดพลาด ปรับค่า อัปเดตแพตช์) ผู้พัฒนาทำได้ทันทีโดยอาศัย log ที่ระบบบันทึก ส่วนการเพิ่ม module หรือพัฒนาใหม่ตามคำขอผู้ใช้ ต้องบันทึกคำขอและได้รับอนุมัติก่อน | ข้อจำกัดด้านอัตรากำลังและผู้เชี่ยวชาญ ใช้มาตรการชดเชยแทนการแยกบุคคล |
| 20 พ.ย. 2569 | หน่วยพัฒนาโปรแกรมรับผิดชอบการพัฒนาระบบ เครื่องแม่ข่าย ฐานข้อมูล ความมั่นคงปลอดภัยไซเบอร์ และ firewall ที่กั้นกลุ่มเครื่องแม่ข่ายกับเครือข่าย | firewall นี้ไม่ได้ใช้กับเครือข่ายทั้งวิทยาเขต ใช้กั้นเฉพาะกลุ่มเครื่องแม่ข่าย |
| 20 พ.ย. 2569 | กำหนดบทบาทของทั้ง 3 หน่วยในงาน IT ในทุกเสา (หัวข้อ 7.1 ของนโยบาย) | ร่างแรกภาระตกที่หน่วยพัฒนาโปรแกรมเกือบทั้งหมด |
| 20 พ.ย. 2569 | ยกระดับเป็นนโยบายระดับวิทยาเขต ชื่อ "CSC-ONE: นโยบายการบริหารจัดการเทคโนโลยีดิจิทัลและข้อมูลของวิทยาเขต" โดยงาน IT เป็นเลขานุการคณะทำงาน รายละเอียดทางเทคนิคแยกเป็นแผนปฏิบัติการและมาตรฐาน | One Data, One Service และ One-Brain ต้องให้หน่วยงานอื่นปฏิบัติตาม |
| 20 พ.ย. 2569 | ใช้ One Architecture เป็นฐาน และให้ One Audit พร้อมก่อนรวมข้อมูลเข้า One Data | ลดความเสี่ยงจากการรวมข้อมูลและจุดเข้าถึงก่อนระบบจะปลอดภัย |

## โครงสร้างงานเทคโนโลยีสารสนเทศ (ณ 20 พ.ย. 2569)

- หน่วยบริการคอมพิวเตอร์และเครือข่ายอินเทอร์เน็ต
- หน่วยโสตทัศนูปกรณ์
- หน่วยพัฒนาโปรแกรม (พัฒนาระบบสารสนเทศ เครื่องแม่ข่าย ฐานข้อมูล ความมั่นคงปลอดภัยไซเบอร์ firewall กลุ่มเครื่องแม่ข่าย)

## เรื่องที่ยังรอตัดสิน

- ผู้อนุมัติงานพัฒนาใหม่ คือเจ้าของระบบ หัวหน้าหน่วยพัฒนาโปรแกรม หรือทั้งสองฝ่าย
- ระบบ log ปัจจุบันเก็บสำเนาในที่ที่ผู้แก้ไขระบบลบหรือแก้ย้อนหลังไม่ได้แล้วหรือยัง
- ค่าเป้าหมายตัวชี้วัดในหัวข้อ 8 (ยืนยันหลังเก็บค่าฐาน)
